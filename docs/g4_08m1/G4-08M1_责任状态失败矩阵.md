## 3. Player action / durability 状态矩阵

| 状态 | Durable? | 下一步 | retry/restart rule |
|---|---:|---|---|
| submitted action (`action_id`) | caller-stable | first Provider adjudication | raw text alone is not identity |
| invalid/no proposal | no | retry first Provider | RNG invocation count stays 0 |
| `NO_CHECK` + narrative | Conversation acceptance only | normal one-call completion | no check record |
| valid frozen proposal | in-process until resolution commit | Program RNG once | validation completes before RNG |
| resolved check | yes, World CAS mutation | second Provider narrative | same `action_id` reuses exact proposal/roll/outcome |
| narrative failed/cancelled | resolution remains durable | retry second Provider | never reroll; Player action not appended twice |
| accepted resolution narrative | Conversation durable | normal continuation | duplicate submit returns existing accepted result |

Stable identities:

- caller supplies non-empty safe `action_id`;
- `check_id = "check-" + SHA-256(game_id + U+001F + action_id)`;
- World mutation id is `"public-d20-" + check_id`;
- one action maps to exactly one check; same action with changed Player text fails loud.

## 4. Failure matrix（packet A-E）

| Case | Failure point | Required durable state | Required retry behavior |
|---|---|---|---|
| A | first Provider fails / envelope invalid | no check | retry adjudication; no RNG |
| B | resolution persisted; second Provider fails | exact proposal + rolls + outcome | skip first Provider and RNG; reuse result |
| C | process exits after resolution before narrative | same as B on disk | fresh open/retry reuses result |
| D | duplicate submit | at most one check for action | CAS replay or existing record; no second roll |
| E | narrative accepted then replay | one Player action + one GM response | return accepted continuation; no duplicate append |

Additional failures:

- no selected capability: preserve G4-07 one-call continuation; no envelope/RNG/check state;
- unknown materialized `capability_id`: fail loud at bind/open boundary;
- duplicate exact Expansion or exclusive slot collision: review fails before Final Create side effects;
- invalid DC/modifier/stance/unknown envelope field: fail before RNG;
- persistence conflict/query failure: no second Provider call and no accepted narrative;
- Source current later moves: created Game remains bound to materialized exact generation.

## 5. Program bounds / authority freeze

- DC is an integer in `10..30`, the narrowest continuous range containing the frozen 10/15/20/25/30 guidance.
- modifier is an integer in `0..6`, matching the first-generation +0/+2/+4/+6 semantic scale without creating an Attribute system.
- stance is exactly `normal | advantage | disadvantage`.
- roll faces are Program-generated integers `1..20`.
- `normal` consumes one face; `advantage` / `disadvantage` consume two and select high / low.
- success is only `selected_roll + modifier >= dc`; natural 1/20 has no override.
- envelope uses exactly `NO_CHECK` (`decision/reason/narrative`) or `CHECK_REQUIRED` (`decision/proposal`) and rejects unknown fields.
- model-supplied roll/total/outcome fields are unknown fields and therefore cannot become authority.

## 6. Schema decision

No production physical SQLite migration is required. Resolved checks are bounded opaque Game-local World document data committed through existing v4 CAS `commit_world_mutation`. Historical checks remain audit/provenance and are not injected wholesale into every context. Downstream fictional consequences remain owned by existing World/Character/Conversation owners.
