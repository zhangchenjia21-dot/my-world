# 游戏库合同 v0.1

Status: G4-04 production contract

## 1. Owner boundary

Game Library 是 Application 层的 durable index/current selection owner：

```text
Game record identity
+ player-safe display metadata
+ storage kind / exact safe database resolution
+ current/latest selection intent
+ legacy adoption bookkeeping
```

它不拥有 World、Timeline、Save、Conversation、Recovery checkpoint、Source selection/pin 或 Runtime live state。每个 Game 的 gameplay truth 仍在自己的 SQLite 与既有 G3 Domain/Persistence owner 中。

## 2. Physical topology

第一代固定为：

```text
One Game = One SQLite
```

新 managed Game 的 path 只能由 identity 推导：

```text
user://my-world/games/<game_id>/game.sqlite
```

G3 legacy Game 是唯一 special case，原位采用：

```text
user://my-world/current-game.sqlite
```

Legacy adoption 不移动、复制或删除 DB、WAL、writer lock、backup/recovery 或 quarantine evidence。

## 3. Metadata authority

默认 metadata root：`user://my-world/game-library`。

```text
records/<game_id>.json
current.json
```

Record schema 只包含 `schema_version/game_id/display_name/storage_kind`。Managed absolute path 不持久化；由 safe ID 与 managed root 推导。current 只包含 schema 与明确 game_id，不按 DB mtime、目录顺序、文件名或 Timeline 猜测。

所有 metadata 使用 complete temporary sibling + flush + same-volume atomic rename。`.pending-*` 不属于 inventory。publish failure 不改 Game DB、不破坏旧 current；retry 必须重新验证并安全收敛。

## 4. Open / switch contract

```text
resolve exact record/path
→ require DB file already exists
→ Runtime.open_existing_game
→ require runtime.game_id == record.game_id
→ commit current
→ bind one Game Session
```

Missing DB 在 Runtime/SQLite 前 fail-loud，绝不调用 historical first-run creation seam。Identity mismatch 时立即 close Runtime、释放 writer，不修 metadata、不切 current。

Switch 必须先 cancel/close A 的 Provider/View/SQLite/writer，再打开 B。同一 Application 最多持有一个 writable Game Session；不同 per-Game SQLite 的 writer/backup/recovery root 保持物理隔离。

## 5. Public seam

`游戏库公开接口.gd` 提供：

- metadata-only `list_games` / `get_current_selection`；
- `resolve_current_existing_game` / `resolve_existing_game`；
- `commit_current`；
- verified existing managed/legacy registration；
- safe managed path derivation与唯一 legacy path。

Application Shell 负责真实 Runtime identity cross-check、legacy adoption 与 Session close/open ordering。Game Library inventory/restart query 不打开所有 Game DB。

本合同不提供 shared SQLite、Game creation、Source chooser/composition、Final Create、Source pin、Expansion、uninstall/delete、cloud 或 Provider 能力。
