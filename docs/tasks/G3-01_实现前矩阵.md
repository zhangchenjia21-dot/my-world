# G3-01 实现前矩阵

本文件是 G3-01 technical spike 的任务期 working note，用来在数据库实现之前冻结 owner、真相类型与失败预期。它不是长期 canonical architecture，也不冻结 G3-02+ 或 G5 的 production schema；Independent Review 后的正式架构传播仍由 `Vibe-Coding` 现有 canonical 文档承担。

## Ownership Matrix

| 对象 | Canonical owner | 真相类型 | Durable | Timeline-scoped | Restore 处理 | 可写方 | 只读方 |
|---|---|---|---|---|---|---|---|
| Game | Persistence Domain 中的 Game aggregate lifecycle | Authoritative identity / lifecycle root | yes | no；Game 拥有 Timeline | 同一 `game_id` 保持稳定，只切换 active head | Persistence mutation flow | UI、Conversation、Context、后续 World Runtime |
| World State | Game-local World Domain；Persistence 保存 active head 对应的 authoritative materialization | Authoritative gameplay truth | yes | yes | 原子切换到目标 head 的可恢复状态；不得与新 head 混合 | 后续 G3-02 World mutation flow，经 Persistence transaction | UI projection、Conversation/Context material provider |
| Timeline | Persistence Domain | Authoritative durable history/recovery relationship | yes | 属于 Game；自身定义 scope | 保留同一 Game 的节点关系与未被删除的旧 future | Persistence mutation/restore flow | Save、UI projection、Conversation/Context association |
| Timeline Node | Timeline owner | Authoritative durable recovery anchor/reference target | yes | yes | 目标节点成为新的 active head；旧 current future 仍由 durable reference 保留 | Persistence transaction only | Save Point、恢复流程、派生 Timeline projection |
| Save Point | Save/Timeline Domain；底层由 Persistence 持久化 | Authoritative named reference + player metadata，不是 World 副本 | yes | 引用某一 Timeline Node | Save 本身不变；Load 解析其 node reference 后切 head | 后续明确 Save intent flow | UI、restore flow |
| Conversation | Conversation Domain | Authoritative accepted gameplay conversation history；不是 World truth/Timeline identity | conditional：G3-03+ 才 materialize | yes，记录必须绑定 Game 与可见 head/range | 只恢复目标 head 可见的 accepted history；未来记录不得泄漏 | Conversation Domain，经后续持久化边界 | Context Assembly、Narrative UI、Persistence adapter |
| Agent Context | Context owner；当前为 Context Assembly | Derived；未来 summary 也只能是可失效 cache/material | no by default；future cache conditional | 必须绑定 head 或明确有效范围 | 丢弃/失效并从 restored World + Conversation 重建 | Context Assembly；future cache writer | Provider request builder |
| UI Preference | UI Preference owner（独立于 Game/Timeline） | Authoritative preference，但不是 gameplay truth | conditional，独立 settings persistence | no | Game Restore 不回滚、不改写 | Settings/UI Preference flow | UI |
| Source / World Pack material | World Pack / Source owner | Reusable reference；不是运行中 game-local truth | yes，独立资产生命周期 | no | Restore 继续按持久化 provenance/reference 解析；不得用 Source 覆盖本局 reality | G4 import/authoring flow | Game creation/materialization、Context |
| Derived UI / Transcript / Cache | 各投影/缓存 owner | Derived / Cache | no by default | 若缓存存在则必须显式绑定 head | 丢弃并由 restored authoritative state 重建 | 对应 projector/cache writer | 玩家界面或内部消费者 |

### Ownership 不变量

- `Conversation != Timeline`：Conversation 拥有 accepted turn truth；Timeline 拥有 durable recovery anchors。
- `Save Point != Timeline Node`：Save Point 是玩家命名的 node reference，不复制 World truth。
- active World、active head 与新 Timeline Node 是一次 durable mutation 的同一原子边界。
- UI Preference 在 gameplay timeline 之外，Game Restore 不得回滚它。
- `Conversation.get_context_projection()` 与 Context Assembly messages 是一次性 derived material，不持久化为 fallback truth。
- 未来任何 Context summary/cache 必须绑定 head/validity range，Restore 后失效或重建。
- Source 只提供 reusable 起点；开局后的 game-local reality 才是本局 authoritative truth。

## Failure Matrix

| 场景 | 分类 | Spike 操作/注入点 | 必须观察到的结果 | G3 v0.1 处理方向 |
|---|---|---|---|---|
| normal commit | 正常路径 | 同一 transaction 写 fixture World value、新 Timeline Node、active head | 三者全部可见，reopen 后 exact values 保留 | 成功才发布新 durable head |
| transaction rollback | Persistence integrity path | 写完多表后显式 `ROLLBACK` | 三者均不可见，last committed state 不变 | fail-loud；不从 UI/Transcript 补状态 |
| process dies before COMMIT | Persistence integrity failure simulation | 隔离 helper 在 transaction 内写入后，以 exact PID deterministic terminate | reopen 只见 last committed state，没有半新半旧 | SQLite rollback journal/WAL + startup read validation |
| process dies after COMMIT | 已提交后进程中断 | helper `COMMIT` 后立即退出/被终止，再 reopen | 新 state/head/node 全部存在 | COMMIT 是 durable visibility boundary；UI ack 需在成功后 |
| DB reopen | 正常恢复路径 | close connection/process 后新进程 open | stable `game_id`、head、state exact match | G3-03 再实现产品 resume |
| schema migration success | 正常升级路径 | transactional N → N+1，更新 schema version + fixture column/table | version 与结构一起升级，旧数据仍可读 | 显式、有序、transactional migration |
| schema migration fails midway | Persistence integrity failure | transaction 内执行部分 DDL/DML 后注入 SQL error | version 仍为 N，部分变更不可见，旧 schema/data usable | rollback；未来 destructive migration 前另做可恢复 backup |
| DB file missing | 可恢复环境状态 | 打开明确的新测试路径 | 只在明确 create/open-new 流程创建；未知路径不自动猜测 | 产品层区分 new game 与 missing expected game |
| DB file unreadable/corrupt | Persistence integrity failure | 对隔离、明确 identity 的损坏 fixture reopen | open/read 失败可见；不得新建空库冒充原 Game 或从 Transcript 恢复 | fail-loud，保留原文件供后续 G3-06 recovery/backup |
| Save points to valid old timeline node | 正常 Restore intent | H5 active，Save 指向 H2 | Save resolve 到 H2；切 head 不复制平行 World truth | G3-04 实现 explicit Load/Restore |
| active head moves after old Save restore | 正常 Timeline 演化 | H5 → restore H2 → 后续从 H2 产生新 node | H3..H5 不立即删除，旧 future 有 durable reference；新 future 有明确 parent | G3-05 冻结 recovery/branch product flow |
| model/Narrative mistake | Logical game mistake | 不进入物理故障注入 | Persistence 不审查普通叙事正确性 | Cancel/Regenerate/correction/explicit Restore 处理 |

### 本次 spike 选择的真实验证项

本次实现必须真实覆盖：normal commit、explicit rollback、pre-COMMIT process termination、post-COMMIT reopen、migration success、intentional migration failure rollback、missing-path create、corrupt/unreadable fail-loud、stable identity，以及 exported Windows EXE 的 open/write/reopen/read。Save/old-future 关系只用最小 fixture 证明 durable references，不实现 Save UI 或 production Restore flow。

### Proposed minimal G3 architecture

```text
Game aggregate identity
├─ active Timeline head reference
├─ authoritative current World materialization
├─ Timeline Nodes + checkpoint/snapshot anchors
├─ Save Points -> named Timeline Node references
├─ Conversation records -> Game + visibility head/range association (G3-03+)
└─ future Context cache -> head-bound, invalidatable, rebuildable (not truth)

UI Preference
└─ separate settings lifetime; never rolled back by Game Restore
```

一次 production durable mutation 的建议原子边界：

```text
authoritative World changes
+ new Timeline Node / mutation metadata
+ checkpoint/snapshot material when required
+ Game.active_head_id
→ one SQLite transaction
→ COMMIT 后才对调用方发布成功
```

Restore 的第一代方向是：目标 Save 解析到可恢复 Node；切 head 前为旧 current head 建立 recovery reference；旧 future 不立即物理删除；Conversation/Context 只读取 restored head 可见范围。具体 product flow、backup policy、production schema 与 recovery UX 仍留给 G3-02～G3-06。

Migration/backup 边界冻结为：schema version 存在数据库内的单一明确 source；migration 按版本有序执行并由一笔 SQLite transaction 包围；任何 destructive migration 前先用 SQLite online backup 能力生成带原版本/identity 的恢复副本并验证可打开，再开始 migration。migration 失败必须 rollback、保留原 DB 与 backup、fail-loud，绝不创建空库或借 UI/Transcript 冒充恢复成功。G3-01 已真实证明 transactional success/failure；production backup 命名、保留策略与自动恢复流程属于 G3-06。

Snapshot/checkpoint 只作为某个 Timeline Node 的 immutable recovery/performance anchor；active current World materialization 仍是运行时唯一 authoritative current state，Snapshot 不作为第二套 live state 被并行写入或读取。
