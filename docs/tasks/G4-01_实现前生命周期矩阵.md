# G4-01｜实现前生命周期 / 失败矩阵

## 1. 边界与状态语义

本矩阵在修改生产代码前冻结 G4-01 的最小生命周期语义：

```text
Application Lifetime != Game Session Lifetime
```

等价状态：

```text
Application: BOOTING -> MENU_READY -> OPENING_GAME -> GAME_ACTIVE -> EXITING
Session:     ABSENT  -> OPENING    -> READY       -> CLOSING    -> FAILED
```

`FAILED` 是一次显式 Continue 的结果，不等于 Application 失败。除 Application 正在退出外，Session 失败后 Application 回到可理解、可重试的菜单态。

## 2. 生命周期 / 失败矩阵

| 场景 | Application state | Game Session state | SQLite open / lock | Conversation / generation | UI surface | 玩家可见结果 | Cleanup | Durable side effects | Forbidden side effects | Retry / reopen |

| A. 启动，已有合法 current Game | `BOOTING -> MENU_READY` | `ABSENT` | 不打开连接、不取 writer lock | 不 rehydrate Conversation；无 Provider state | Main Menu | 看到“继续游戏 / 新游戏 / 退出游戏” | 无 Game cleanup；Application 保持运行 | 无 | 启动时读取 Game、刷新备份、改 DB、持锁或先闪入 Game | 显式 Continue 才进入 C |
| B. 启动，current Game DB 不存在 | `BOOTING -> MENU_READY` | `ABSENT` | 不创建 DB/目录，不打开连接，不取 lock | 不创建 Game-owned Conversation/Provider | Main Menu | 菜单正常可用；不伪装已有游戏 | 无 | 无 | 启动即 mint 空 Game、创建 SQLite 或 recovery material | Continue 可调用既有 G3 opener；只有该显式动作可按现有 one-current-Game contract 建立首个 Game |
| C. | D. | F. ## 3. 编码前发现与最小实现决策

1. `src/应用壳.gd::_enter_tree()` 当前自动构造 Runtime 并打开 DB，必须退休；Application `_ready()` 只建立菜单与应用级事件。
2. `CurrentGameRuntime.open_current_game()` 已拥有 one-current-Game、missing DB 显式创建、rehydration、single-writer、backup/corruption 的正式语义；Continue 必须直接复用，不复制。
3. `CurrentGameRuntime.close()` 已负责 Conversation attempt abandon、verified backup refresh、SQLite close 与 writer release；无需 schema 或 persistence ownership 变更。
4. 仅调用 `Runtime.close()` 不足以取消 `叙事对话视图` 内实际 `DeepSeekProviderAdapter` transport。Game Session close 必须先调用 View 的窄 shutdown seam，让 adapter cancel，再 close Runtime并释放 Game Surface。
5. Game Surface 应按 Session 生命周期实例化/释放；Main Menu READY 时 Narrative View 不应存在，避免它建立 Game-owned Conversation/Provider state。
6. Continue startup failure 属于 Application surface：普通失败显示可理解原因；物理损坏沿用中央说明与紧邻恢复动作。恢复完成的旧 Runtime 必须释放，下一次 Continue 使用新 Runtime reopen。
7. New Game 只切换到稳定、诚实的 Application host；不创建 DB、不写 Source metadata、不引入 routing/framework。
8. Quit、Windows close 共用一个退出入口；若 Session 存在，先走与 Return 相同的 cleanup，再退出。

## 4. 架构检查结论

- Application Shell 是现有 composition root，允许直接拥有菜单与当前 Session 的创建/关闭编排。
- Game Runtime 继续只跨 Persistence 的 `L3_外交层`；本任务不新增跨模块内部直连。
- 不需要新增通用路由器、事件总线、DI 容器或状态机框架。
- 不需要修改 production schema、Game identity、Save/Timeline/Recovery 语义或 multi-Game topology。
- 因此矩阵未发现 packet 规定的架构级 blocker，可以进入最小实现。
