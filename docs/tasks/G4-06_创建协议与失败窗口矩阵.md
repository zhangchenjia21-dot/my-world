# G4-06 创建协议与失败窗口矩阵

Status: implementation prerequisite  
Task: G4-06 Atomic Final Create  
Schema Gate: **不修改 production SQLite schema**。完整初始 setup envelope 写入 schema v4 已有的 opaque World document，并同时成为 root Timeline snapshot。

## 1. 提交协议

```text
无 durable 副作用的 exact Composition 复核与 Source 投影
→ 原子发布 immutable creating intent
→ 取得目标 Game DB single-writer ownership
→ 原子创建 initial Game + root Timeline + current World + empty Conversation
→ 复读 DB identity 与 immutable root snapshot
→ 原子发布 verified Game Library record
→ 原子发布 current selection
→ 原子发布 created marker
```

`creating intent` 与 `created marker` 是 Application 创建协议 metadata，不是 gameplay truth。每个文件均以同目录完整临时文件写入、flush，再以同卷 rename 发布；残留 `.pending-*` 不具权威性。跨 filesystem metadata、Game SQLite、Game Library 不宣称全局 ACID，恢复只按 durable inspection 向前收敛。

## 2. Immutable intent 与 identity

Intent 固定：

- `creation_id`、`composition_fingerprint`；
- `game_id`、root Timeline node ID、Game-local World ID；
- Player 与每个 Guaranteed NPC 的 Game-local Character ID；
- 首次复核后得到的 exact Source pins 和 selected projections；
- 完整 initial setup envelope 与固定 `created_at`。

同一 `creation_id` 只对应一个 intent 文件和一个固定 Game DB path。重试不得重新生成任何上述 identity。Source `asset_id` 只留作 provenance，不能充当 local identity。

## 3. Composition fingerprint canonicalization

fingerprint 对下列 canonical JSON 求 SHA-256：

- exact World pin：`asset_type / asset_id / version / generation_fingerprint`；
- `entry_id`：明确字符串，未选择时明确为 `null`；
- `expansions`：当前固定为空数组；
- exact Player Character pin；
- exact Guaranteed NPC pins：按四元组字典序排序，因为当前 Composition 将其定义为集合而非玩家排序；
- `display_name`；
- `control_mode`；
- `opening_supplement` exact text。

所有 Dictionary key 递归排序后编码。不得包含 UI focus、chooser/list 枚举顺序、Source current pointer、managed/external filesystem path、显示用缓存或 runtime object。

## 4. A–T 状态 / 失败矩阵

| Case | intent / fixed identity | DB physical + internal identity | Library record / current | journal / visible result | retry / restart convergence |
|---|---|---|---|---|---|
| A 首次成功 | 原子发布完整 creating intent | 创建 exactly one SQLite；internal `game_id`、root ID、root snapshot exact | identity 复核后登记 record，再发布 current | created marker；返回 `created` | 再调用走 B |
| B exact replay | 已有 intent，fingerprint exact | 复核同一路径、同一 internal ID 与 root snapshot | exact record/current 为 already 状态 | 已有或补发 created marker；返回同一 Game/local IDs | 不 mint 新 ID、不建第二 DB |
| C 同 creation、不同 payload | fingerprint 与 intent 不同 | 不打开/创建 DB | 不读写 record/current | `creation_payload_conflict` | 永久 fail-loud，既有 truth 不变 |
| D intent 后、DB 前中断 | creating intent durable | DB 不存在 | 无 record/current | 无 marker；注入失败可见 | fresh object 读 intent，使用固定 ID 创建 DB 后继续 |
| E DB 后、record 前中断 | intent durable | matching DB + root durable | 无 record/current | 无 marker；注入失败可见 | 复核 DB 后登记 record/current，不重建 DB |
| F record 后、current 前中断 | intent durable | matching DB | matching record；current 仍旧/无 | 无 marker；注入失败可见 | record exact replay，再发布 current |
| G current 后、caller success 前中断 | intent durable | matching DB | matching record/current | 无 marker；注入失败可见 | 复核所有 durable state，补发 marker，返回同一 Game |
| H Source missing/tampered | intent 尚未发布 | 无 DB | 无 record/current | exact lookup/projection 失败 | 修复 Source 后可重新尝试；零 Game 副作用 |

| L non-temporal Character 无 profiles | intent 含 top-level rich semantics | 正常创建 | 正常发布 | created | 不创建假 profile |

| P record/current publish 失败 | intent durable | verified valid DB 保留 | 失败点之前的完整 metadata 保留 | 无 marker，错误可见 | 重试向前发布；不删除有效 DB |

| S Owner real data isolation | 测试显式注入 creation/library/games/source roots | 仅 task-owned SQLite | 仅 task-owned metadata | 仅 task-owned journal | 不触碰 production `user://` 或 Owner 资产 |
| T no Provider / AI Opening | intent/setup 不含 Provider result | Conversation 初始为 durable empty array | 与 Provider 无关 | terminal=`created` | 零 Provider request、零 AI turn，不宣称 playable |

## 5. Materialization 决策

- 有 exact Entry：World = top-level always-safe + exact Entry；Character = top-level always-safe + exact matching profile；zero coverage 则 Character top-level-only。
- 无 Entry：World 与所有 Character 均只复制 top-level `semantic_sections`，不得调用或推断 Entry/profile。
- setup envelope 保留 section ordering、disclosure、selected Entry/profile metadata 与 exact provenance pin，但不复制任何未选择 Entry/profile 的 bytes。
- Guaranteed NPC 只进入 canonical local cast；不写 opening presence、current location、player-known 或 relationship。
- initial Conversation 保持空；G4-06 不调用 Provider、不生成 Opening。
