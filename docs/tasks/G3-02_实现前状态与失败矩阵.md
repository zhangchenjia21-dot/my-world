# G3-02 实现前状态与失败矩阵

本文件在 production schema/代码之前冻结 G3-02 的状态转换与失败语义。它是 task-scoped working note，不是长期 canonical architecture，也不冻结 G5 的 NPC/Faction/Item/Quest schema。

## 1. Production 职责与分层

| 职责 | 层级 | 理由 |
|---|---|---|
| 持久化操作状态与公开结果形状 | `L0_公理层` | 表达调用方可依赖的稳定结果契约，不做 I/O |
| opaque World document 校验、递归 key 规范化与 intent fingerprint | `L1_器件层` | 单一、确定性的可复用完整性机制，不解释 World 业务语义 |
| SQLite 连接、PRAGMA、parameter binding、transaction 基础操作 | `L1_器件层` | 集中 Godot SQLite binding 细节，不编排业务用例 |
| schema v1、initial Game 与 durable mutation transaction | `L2_流程层` | 拥有步骤顺序、CAS expected head、replay/conflict 与 rollback |
| 明确 DB path 的 production API | `L3_外交层` | 对外暴露稳定 DTO/结果，不泄露 SQLite rows 或内部连接对象 |

依赖保持 `L3 -> L2 -> L1 -> L0`。本任务没有跨业务模块调用；Game/World/Timeline identities 与 opaque materialization 由调用方提供，Persistence 只拥有 durable representation/transaction mechanics。

## 2. State / Failure Matrix

基准状态：Game 尚不存在，随后创建 `G1 / H0 / W0`。一次正常 mutation `M1` 从 `H0` 提交到 `H1 / W1`。Node count 包含 root node。

| 场景 | Active head before → after | World before → after | Node count before → after | 调用方结果 | Partial durable visibility |
|---|---|---|---|---|---|
| create initial Game/root head | absent → `H0` | absent → exact `W0` | 0 → 1 | `committed`；返回 root result | none；Game/current World/root anchor 同事务 |
| duplicate Game identity | `H0` → `H0` | `W0` → `W0` | 1 → 1 | `already_exists` | none；绝不覆盖 |
| normal mutation commit `M1` | `H0` → `H1` | `W0` → exact `W1` | 1 → 2 | `committed` | none；COMMIT 后才返回成功 |
| same `M1` replay after success | `H1` → `H1` | `W1` → `W1` | 2 → 2 | `replay_success`；返回已提交 `H1` | none；不重复 effect/node |
| same `M1` after simulated lost ACK | `H1` → `H1` | `W1` → `W1` | 2 → 2 | `replay_success`；恢复同一 committed result | none；caller 未见 ACK 不改变 durable identity |
| same `mutation_id=M1` with changed parent/node/materialization | `H1` → `H1` | `W1` → `W1` | 2 → 2 | `mutation_conflict` | none；fingerprint mismatch 明确拒绝 |
| new `M2` with stale `expected_head=H0` | `H1` → `H1` | `W1` → `W1` | 2 → 2 | `stale_head` | none；不自动 rebase/merge |
| late SQL failure during new `M2` | `H1` → `H1` | `W1` → `W1` | 2 → 2 | `storage_failure` | none；先写 node/current World 后，最终 head UPDATE abort，整笔 rollback |
| reopen after committed mutations | `H1` → `H1` | `W1` → exact `W1` | 2 → 2 | read success | none；stable Game/head/node/mutation identities 保持 |
| invalid/non-serializable World input | unchanged | unchanged | unchanged | `invalid_input` | none；在 BEGIN/SQL 前拒绝 |

## 3. Durable invariants fixed before schema

- current World materialization 是唯一 writable live authoritative materialization；Timeline Node snapshot 是 immutable historical recovery anchor。
- 一次 commit 同事务写入新 Node/immutable snapshot、替换 current World、CAS 更新 `Game.active_head_id`。
- `mutation_id` 在同一 Game 内唯一；exact replay 先于 stale-head 判断，从而允许更晚重试已提交 intent。
- intent fingerprint 覆盖 `game_id + mutation_id + expected_head_id + node_id + canonical next World document`；Dictionary insertion order 不影响 fingerprint。
- 新 mutation 必须在 `BEGIN IMMEDIATE` 内重新读取 current head，不能依赖 transaction 外的旧 read。
- 任何 SQL/COMMIT failure 都 rollback 并返回可观察错误；UI/Transcript/Context 不参与补偿或 fallback。
- Persistence 只验证 JSON 可持久化结构、finite number、String dictionary keys 与 identity/integrity；不判断 Narrative/lore 是否合理。

## 4. Minimal schema direction

production schema v1 仅表达：

```text
persistence_schema
games
world_materializations
timeline_nodes
```

它不会复制 `g3_fixture_*`，不会包含 Save Point、Conversation、NPC、Faction、Item、Quest 或 World Pack tables，也不会建设 ORM/full event sourcing。
