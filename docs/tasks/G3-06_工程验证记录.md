## 实现边界

- dedicated sibling coordination SQLite 持有 process-lifetime `BEGIN IMMEDIATE`；第二进程 `busy_timeout=0` fail-fast。正确性来自 Windows/SQLite live file lock，artifact/PID/time 不作 authority。
- gameplay DB 不持有 lifetime transaction；production backup 使用 `SQLite.backup_to(path)`，replacement staging 使用 `SQLite.restore_from(path)`。
- `<db-base>.recovery/latest.sqlite`、`previous.sqlite`、`backup-staging.sqlite` 与 `replacement-staging.sqlite` 采用验证后发布；物理损坏 current 先移入唯一 quarantine 子目录，再发布已验证 replacement。
- startup 顺序为 writer ownership → physical/schema classification → pre-migration verified backup → existing persistence migration/open → logical rehydration → initial verified backup → READY。
- Save COMMIT 后刷新 backup；刷新失败不撤销 Save，返回准确 warning。graceful close 尽力刷新且不破坏旧 verified generation。
